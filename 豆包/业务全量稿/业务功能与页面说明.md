# 她记 HerLog · 业务全量稿说明

> 版本：V1.0（2026-11-19）  
> 依据：`女性健康记录助手需求文档.md`（V0.8）+ `女性健康记录助手UI-UX设计文档.md`（V1.0）  
> 视觉基线：`风格方案/01b-蜜桃奶油·素材版`（蜜桃渐变 + 纸感卡片 + 背景插画 + 卡通头像）  
> 基准尺寸：390 × 844（截图 @2x）；色值、圆角、按钮高度沿用 `前端样式/styles.css` 与 `theme.css`

## 一、先给结论：为什么是 21 屏

这套稿子的拆分原则只有一句：**一级页回答"今天怎么样、要记什么"，二级页承担"翻旧账、看细节、讲口径、做设置"。**

| 判断 | 处理方式 | 原因 |
|---|---|---|
| 每天都要看 / 每天可能记 | 留在一级页（5 屏） | 减少点击层级，打开即用 |
| 录入只有 3–8 个字段、且需要看到上下文 | **底部半屏**，不跳页（3 屏） | 经期要看着日历选日期，体重只需数字键盘；跳页会丢失上下文 |
| 列表会变长、需要筛选 / 编辑 / 删除 | 独立二级页 | 一级页塞不下，且会挤掉"今天"的信息 |
| 需要解释规则、免责、边界 | 独立二级页 | 一段提示文字讲不清预测与 AI 的边界，单独成页才能完整阅读 |
| 低频账号动作（设置、隐私、关于） | 独立二级页 | "我的"首屏只保留资料与退出，避免越用越长 |
| 登录 / 注册 | 独立两屏 | 未登录时的唯一入口，需要独立状态 |

**总计：5 个一级页 + 16 个二级页 = 21 屏**（其中 3 个二级页是一级页上的半屏表单）。

## 二、一级页：功能与设计

### 1. 首页 · 今天（`home.html`）

| 区块 | 功能 | 设计要点 |
|---|---|---|
| 页首摘要 | 日期、星期、经期状态（第几天 / 最近开始）、最近体重 | 只读，不提供编辑；一句话告诉用户"今天处于什么状态" |
| 三个快捷入口 | 记经期、记体重、拍照分析 | 分别跳到 `period-record` / `weight-record` / `skin-capture` 对应的半屏或流程；首页不重复实现表单 |
| 问答区 | 只读文字问答，示例问题 chips | 回答只引用已保存记录；不改记录、不生成草稿、不发送皮肤原图 |
| 输入条 | 贴底的单行输入 + 发送圆钮 | 长回答在消息流里滚动，输入条不遮内容 |

**刻意不放**：趋势、历史、建议、设置。它们各自有归属页，首页重复入口只会让"今天"变重。

---

### 2. 经期（`period.html`）

| 区块 | 功能 | 设计要点 |
|---|---|---|
| 状态行 | 「经期第 N 天」/「最近开始」/「暂无记录」 + 开始日期标签 | 预计日期**不算**实际经期；没有记录时不编造"第 1 天" |
| 预测摘要 | 预计下次开始 + 「怎么算的 ›」 | 摘要只给结论，口径与异常状态交给二级页解释 |
| 月历 | 月份切换、七列、今天描边、实际经期连续色带、预计日虚线、感受小圆点、图例 | 实际用实色连续带（17–19 连成一条）；预计只描边；感受点不改变日期底色 |
| 当天记录 | 当天已记录的经量/腹痛/疲惫 chips + 两个入口 | 原地展示，避免用户重复记录；两个入口都打开半屏 |
| 历史入口 | 「共 3 段 ›」→ `period-history.html` | 一级页只给最近摘要，完整列表进二级 |
| 免责 | 「根据历史记录估算，实际日期可能不同，不作为避孕依据」 | 固定放在预测摘要与历史区，不折叠 |

**两个半屏**

- **记录经期（`period-record.html`）**：开始 / 最后一天两个段选项；显示开始日、最后一天、持续天数；若所选日期落在已有经期内，给"重叠提示"，**不自动覆盖**；提供"删除本段经期"。
- **记录感受（`period-feelings.html`）**：经量、腹痛、其他不适、情绪、生活影响、备注；**只填一项也能保存**；明确"单独记录感受不会新建一段经期"。

> 为什么用半屏：选日期时用户需要看到月历上 17–19 的连续色带；跳页会丢失这个判断依据。半屏还能下滑关闭，等同取消。

---

### 3. 体重（`weight.html`）

| 区块 | 功能 | 设计要点 |
|---|---|---|
| 最近测量 | 超大数字 + kg、时间、标签、记体重按钮 | 参考图的"数字主角"；单位弱化，不抢数字 |
| 趋势 | 近 7 / 30 天切换、折线 + 面积渐变、首尾变化、记录次数 | 只画实际有测量的日期；缺测不补值、不连假点 |
| 记录明细入口 | 「全部 8 笔 ›」→ `weight-detail.html` | 逐笔编辑、删除、筛选在二级页完成 |
| 趋势详情入口 | 「查看趋势详情 ›」→ `weight-trend.html` | 一级页是缩略图，点选数据点与统计放二级 |
| 建议 | 一条与"记录情况"相关的建议 | 只谈记录方法（如固定时间称重），不评价胖瘦、不给目标体重 |

**半屏：记体重（`weight-record.html`）**：大数字 + 测量时间 + 标签 + 数字键盘；单位固定 kg；同日多笔全部保留；趋势只取每天最后一次。

---

### 4. 皮肤（`skin.html`）

| 区块 | 功能 | 设计要点 |
|---|---|---|
| 顶部双按钮 | 居中并排「拍照分析」「历史记录」 | 两个高频动作放在页首，一眼可达；主按钮走拍摄流程，次按钮进历史 |
| 最近一次观察 | 大幅照片、拍摄时间、AI 观察标签、已保存状态、三段观察 | 照片在上、结论在下，按"先看照片再读文字"的顺序；只给最近一次，不堆历史 |
| 免责 | 「模型生成的观察文字，不构成诊断」 | 与结果页同一口径；发送说明放在卡片下方，不打断照片阅读 |
| 免责 | 「模型生成的观察文字，不构成诊断」 | 与结果页同一口径，不弱化 |

**完整链路（4 个二级页）**

1. `skin-capture.html`：选部位（一次一个）→ 三条拍摄提示 → 相机/相册 → 确认发送。
2. `skin-result.html`：照片 + 三段（照片中可见 / 看不清的地方 / 下次可留意）+ 观察标签 + **保存 / 不保存 / 重拍**。
3. `skin-history.html`：按时间倒序的观察卡，同部位可对比。
4. `skin-compare.html`：两张照片 + 两段**已保存文字** + 共性/差异 + 「基于两次文字观察」标注。

> 硬规则：**只有点"保存"才写入历史**；不保存、重拍、直接返回都不新增记录；对比绝不重新发送照片；不出现病名、严重度、改善百分比。

---

### 5. 我的（`me.html`）

| 区块 | 功能 | 设计要点 |
|---|---|---|
| 头像与用户名 | 插画头像、昵称、@用户名 | 头像来自 `assets/avatar.png`；用户名只读 |
| 资料表单 | 生日、身高、电话（均选填） | 电话提示"仅作为个人资料，不用于登录，也不会发送验证码" |
| 保存资料 | 主按钮 | 只保存资料，不动健康记录 |
| 设置入口 | 「设置与隐私 ›」→ `settings.html` | 低频动作从首屏拆出 |
| 退出登录 | 次按钮 + 说明 | 退出后账号与记录仍保留，重新登录可见 |

## 三、二级页：16 屏逐个说明

### 经期（4 屏）

| 页面 | 入口 | 页面内容 | 关键设计 |
|---|---|---|---|
| `period-record.html` | 经期页「记录经期」/ 首页快捷入口 | 半屏：开始/最后一天、开始日、最后一天、持续天数、重叠提示、删除本段 | 日期选择保留日历上下文；重叠不自动覆盖；结束日可补记 |
| `period-feelings.html` | 经期页「记录感受」 | 半屏：经量、腹痛、其他不适、情绪、生活影响、备注 | 只填一项即可保存；不新建经期；与日期分开存 |
| `period-history.html` | 经期页「共 3 段」 | 周期列表（开始日、结束日、持续天数、距上次间隔、未记录结束）、年份筛选 | 倒序；进行中单独标记；说明"删除经期不删当天感受" |
| `period-prediction.html` | 预测摘要「怎么算的」 | 预计日期、参与计算的周期、估算过程、四条规则、三种异常状态 | 记录不足 / 极差>7 天 / 已过预计日都明确"不显示日期"；免责固定 |

### 体重（3 屏）

| 页面 | 入口 | 页面内容 | 关键设计 |
|---|---|---|---|
| `weight-record.html` | 体重页「记体重」/ 首页快捷入口 | 半屏：58.2 kg、测量时间、标签、数字键盘 | 单手输入；保存后回原页；同日多笔保留 |
| `weight-detail.html` | 体重页「记录明细」 | 全部/近30天/近7天筛选、逐笔数值与时间、编辑/删除 | 同日多笔不合并；删除只删一笔，趋势重算 |
| `weight-trend.html` | 体重页「查看趋势详情」 | 7/30/90 天切换、可点选数据点、记录次数/首尾变化/数据点、口径说明 | 缺测不补值；不对单次涨跌评价 |

### 皮肤（4 屏）

| 页面 | 入口 | 页面内容 | 关键设计 |
|---|---|---|---|
| `skin-capture.html` | 皮肤页「拍照分析」/ 首页快捷入口 | 部位选择、三条拍摄提示、相机/相册、发送说明 | 一次只观察一个部位；提示自然光、同角度、关美颜 |
| `skin-result.html` | 拍照后 | 照片、AI 观察三段、观察标签、保存/不保存/重拍 | 保存才入库；三段结构固定；免责不折叠 |
| `skin-history.html` | 皮肤页「历史记录」 | 按时间倒序的观察卡、同部位筛选、对比入口 | 照片仅本人可见；只读取已保存文字 |
| `skin-compare.html` | 历史页「选择两次对比」 | 两张照片、两段文字、两次都提到/只有一次提到、口径标注 | 只用两次已保存文字，不重新分析照片；不构成诊断 |

### 我的与账号（5 屏）

| 页面 | 入口 | 页面内容 | 关键设计 |
|---|---|---|---|
| `settings.html` | 我的页「设置与隐私」 | 账号（用户名/个人资料/登录状态）、数据与隐私、关于、退出登录 | 不引入新业务，只做低频动作归位 |
| `privacy.html` | 设置页 | 记录归属、照片与 AI、首页问答、账号注销、可删除项 | 用"能做什么/不能做什么"写边界，不用法律长文 |
| `about.html` | 设置页 | 图标、版本、产品定位、不做什么、免责声明、素材版权 | 合规文本集中，方便版本审查 |
| `login.html` | 退出登录 / 未登录访问 | 用户名、密码、登录、注册入口 | 未登录访问业务页回此页；底部用花瓣线稿插画补氛围 |
| `register.html` | 登录页「注册」 | 用户名、密码、确认密码、注册说明 | 用户名注册后不可改；注册成功回登录，不自动登录 |

## 四、交互约定（写死，避免实现时走样）

1. **一级页常驻五栏底栏；二级页只保留返回圆钮。** 返回目标写死上级页（经期→`period.html`，体重→`weight.html`，皮肤→`skin.html`，设置→`me.html`），不依赖浏览器返回栈。
2. **半屏 = 二级页的一种形态。** 背景加 scrim，面板从底部升起，圆角 24；可下滑关闭；保存按钮固定在面板底部。
3. **保存是唯一写入动作。** 皮肤结果页、经期/体重半屏都遵守；取消 / 重拍 / 返回不产生数据。
4. **日历语义三层。** 实际经期＝实色连续带；预计开始＝虚线描边；感受＝9px 小圆点。三者不叠加成第四种颜色。
5. **数字与日期都用等宽数字（tabular-nums）**，避免切换月份、刷新体重时数字跳动。
6. **所有免责句完整出现，不截断、不缩写。** 经期预测、皮肤 AI、体重建议各自带固定文案。

## 五、业务规则落点（与需求 V0.8 对齐）

| 规则 | 落在哪个页面 |
|---|---|
| 至少 3 次开始记录才预测；取最近最多 4 次；2 个周期取平均四舍五入、3 个取中位 | `period-prediction.html` |
| 最长最短差 > 7 天不显示；已过预计日提示；只有开始日变化才重算 | `period-prediction.html` + `period.html` 状态行 |
| 预计日不当作实际经期 | `period.html` 月历：只描边 |
| 感受与经期分开存；只填一项也能存 | `period-feelings.html` |
| 体重每天取最后一次进趋势；缺测不补；同日多笔保留 | `weight-trend.html` + `weight-detail.html` |
| 皮肤只有保存才入历史；对比只用文字 | `skin-result.html` + `skin-compare.html` |
| 首页问答只读、不改记录、不发原图 | `home.html` + `privacy.html` |
| 退出登录保留数据；用户名只读 | `me.html` + `login.html` |

## 六、视觉延续

- **主色**：`#C0566B`（accent）/ `#9C3B50`（deep）/ `#FBE2E6`（soft）；页面底 `#FDF6F1`，卡片 `linear-gradient(180deg,#FFF,#FFF9F6)`。
- **材质**：卡片 12px 圆角、1px 暖粉描边、内高光 `inset 0 1px 0 rgba(255,255,255,.9)`、低饱和投影。
- **页首**：三层渐变（暖橙 → 粉 → 页面底色）；二级页不叠加插画，避免与内容抢注意力。
- **插画**：头像 `avatar.png`；首页/我的用 `portrait.png` 做页首；登录/注册用 `bloom.png` 做底部花瓣线稿；皮肤页用 `bloom.png` 角落点缀。
- **按钮**：主按钮 48px 高、渐变填充；次按钮白底描边；半屏主按钮贴底。
- **字号**：页首标题 24 / 一级页大标题 28–34 / 正文 15 / 辅助 12–13；日期数字 19–40。

├─ theme.css / business.css / assets.css        # 主题 + 二级页组件 + 素材落位
├─ icons/ (15) / assets/ (头像与插画)

复现顺序：

```powershell
python tools/build_business_base.py   # 复制主题/素材 + 五页
python tools/modify_primary.py        # 打通一级页入口
python tools/build_secondary.py       # 生成 16 个二级页 + 3 个半屏
python tools/fix_pages.py             # 文案与版式修正
python tools/shots_business.py        # Playwright + Edge 截图
python tools/compose.py               # 模块总览图
python tools/build_index.py           # 业务地图
```

> 说明：`assets/` 中插画来自公开素材平台，仅用于本次界面演示；正式上线前请替换为有授权的品牌素材。`login/register` 的底部插画为装饰，不承载信息。
