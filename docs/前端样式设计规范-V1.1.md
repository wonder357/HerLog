## 1　设计方向

**一句话**：这是给身体记账的一本纸页手册，不是一个糖果色的身体数据仪表盘。

`pic/` 里的四张参考图（美柚、好轻类产品）给了两条有效信息：目标用户是女性、产品语气要亲近；也给了三条要丢掉的东西：**高饱和粉紫渐变、玻璃球高光、促销条/对比排行**。前者与「记录」这件事无关，后者会把比赛演示的注意力从「我记了什么」拉走。

所以视觉取「晨雾 · 胭脂 · 纸」：

- **晨雾**：纸底之上压一层极淡的胭脂＋藕荷径向光晕（页面顶部 52% 高度内衰减到 0）。它负责"好看"，且不承载任何语义——截图转灰度后消失也不损失信息。
- **纸**：暖白纸底 `#FDF8F4`；纸面直排区域用发丝线分区，需要浮起来的只有三块（主数字面板、照片、白卡）。
- **胭脂**：主色取干玫瑰方向的胭脂红 `#B2455C`，一个颜色只做一件事——**用户的记录**与主操作；主按钮用同色系 135° 微渐变，是画面里唯一有"体积"的控件。
- **梅紫**：`#6B5680` 只给「预测」和「AI 观察」。用户自己的数据用胭脂，系统算出来的用梅紫，两者在屏幕上永不混色。
- **蜜杏**：`#FBF1E7` 配 `#8A5A2E` 只给"建议、提示、需重拍"这类**旁观者语气**，既不是错误（红）也不是结论（紫）。
- **衬线数字**：日期、kg、第 N 天用衬线（Georgia / Songti SC），界面文字用黑体。数字衬线化 + 界面无衬线，页面才有"一本册子"而不是"一个仪表盘"的气质。

### 与通用 AI 生成式 UI 的三处刻意偏离

| 默认做法 | 本方案 | 原因 |
|---|---|---|
| 每个信息块都是同半径白卡 + `rgba(0,0,0,.1)` 阴影 | **只有三处浮起**：主数字柔光面板、照片卡、功能白卡；其余纸面直排用发丝线 | 记录页信息密度高，卡片堆叠会把「今天记了什么」切碎 |
| 首屏 = 大数字 + 小标签 + 渐变色块 | 首页首屏 = 日期（衬线）+ 问候 + 三个彩色记录入口 + 对话；大数字只出现在**体重页主区之内** | 产品主行为是「记」，不是「看 KPI」 |
| 全大写小标签、`·` 连接元信息、按钮追加 `→` | 中文小标签 12px 次级墨色；元信息用空格或换行；按钮只写动作 | 中文界面里这些西文排版手段会读成翻译腔 |

**唯一允许"抢眼"的地方**：经期日历。它是整个产品最有产品味道的元素，也是预测规则的可见证据（实色/虚线/白点/墨环四态）。其余页面一律克制。

## 2　设计原则

1. **记录优先**：每屏首屏回答一个问题——「我要记什么」。状态、图表、建议都在其后。
2. **形状先于颜色**：日历四态、质量提示、AI 出处都用形状或位置区分，颜色只是加强。色弱用户与黑白截图都成立。
3. **层级靠"浮"不靠"框"**：一屏最多三块浮起（主数字面板 / 照片 / 功能白卡），其余靠字重、字号、发丝线与留白。浮起用**同色系柔影**（`rgba(146,86,86,.55)` 降到 −20px 偏移量），不用中性黑阴影，否则会脏。
4. **数字衬线、界面黑体**：数字有排版感，控件保持中性，两者不混用同一个字体族。
5. **AI 有边界**：AI 段落必带「AI 观察」标识与出处；只读问答的引用必定带日期范围与可跳转的记录入口。
6. **一个动作一个名字**：入口叫「记体重」，按钮就叫「保存体重」，成功提示就叫「体重已保存」。
7. **氛围不承载语义**：晨雾光晕、圆角、渐变按钮都只是气质；把它们的透明度或颜色去掉，页面信息必须完全不变。

### 3.3 字体与字阶

字体族：

```
--hr-serif: Georgia, "Songti SC", "Source Han Serif SC", "Times New Roman", serif;
--hr-sans:  "PingFang SC", "HarmonyOS Sans SC", "Source Han Sans SC", "Microsoft YaHei", system-ui, sans-serif;
```

生产环境建议：数字衬线只打包 **Source Han Serif SC 数字子集**（约 8 KB woff2）；中文标题与正文仍走系统黑体，首屏不引入中文网络字体。

| 用途 | 字号 / 行高 | 字重 | 族 | 备注 |
|---|---|---|---|---|
| 登录产品名 | 40 / 40 | 400 | serif | 字距 .06em；Android 允许回退黑体 600 |
| 首页问候 | 25 / 32 | 400 | serif | 只出现在首页，24 小时按时间换问候语 |
| 页面主数字（kg、第 N 天） | 54 / 56 | 400 | serif | 字距 −.02em；单位 13px 600 rose（体重）、12px ink-2（经期「天」） |
| 页面标题 | 22 / 28 | 600 | sans | 左侧对齐；二级页居中 16/600 |
| 区块标题 | 16 / 24 | 600 | sans | 与上区块间距 14～16 |
| 正文 | 15 / 24 | 400 | sans | 行宽 ≤ 20 个汉字 |
| 卡内正文（AI 三段、建议） | 14 / 22 | 400 | sans | 比正文小一档，给卡片留白 |
| 说明/时间 | 12 / 18 | 400 | sans | ink-2 |
| 标签（chip） | 12 / 16 | 500 | sans | 高 32、左右 13、圆角 999；选中 600 + rose |
| 数字表格（明细行） | 16 / 24 | 400 | serif | kg 数值 |
| 微文案（图例、出处、脚注） | 11 / 16 | 400 | sans | ink-3，不用大写 |

不使用：字间距 > 0.1em 的西文大写小标签、下标角标、`01/02/03` 编号（本研究内容不是序列）。

### 3.4 间距、圆角、描边、阴影

- 间距基数 4；常用节奏 **8 / 12 / 16 / 24 / 32**。页面左右内边距 **22**（360px 宽时 18）。
- 区块间距 14～20；同组元素 8～12；标题与内容 10～12。
- 圆角即层级，**四档就够**：

| 用途 | 圆角 |
|---|---|
| 输入框、名单内嵌块 | 16 |
| 功能白卡、照片、缩略图 | 22（缩略图 16） |
| 主数字柔光面板 / 首页入口方块 | 26 / 22 |
| 主按钮、chip、分段、浮动底栏 | 999 / 999 / 999 / 24 |
| 底部弹层上沿 | 30 |

- 描边：发丝线 1px `--hr-line`；可行控件（描边按钮、分段、输入框）1px `--hr-line-2`；选中与错误用色描边，**不用阴影代替边框**。
- 阴影只用同色系柔影，共四档（`rgba(146,86,86,α)`，把 α 与偏移当作"浮起高度"）：

| 层级 | 阴影 |
|---|---|
| 白卡 / 柔光面板 | `0 14px 34px -20px rgba(146,86,86,.55)` |
| 浮动底栏 | `0 14px 34px -12px rgba(120,70,70,.34)` + 内描边 `inset 0 0 0 1px rgba(255,255,255,.85)` |
| 主按钮 | `0 10px 22px -12px rgba(166,59,82,.9)` |
| 吸底输入条 | `0 14px 30px -16px rgba(120,70,70,.4)` |

- 晨雾底（每个一级页统一，写在页面根节点）：

```css
background:
  radial-gradient(115% 52% at 16% -6%, #FDEDEE 0%, rgba(253,237,238,0) 58%),
  radial-gradient(80% 34% at 96% 4%, #F2ECF7 0%, rgba(242,236,247,0) 60%),
  var(--hr-paper);
```

只允许这两层，不得再叠条纹、噪点或网格；浅色模式下晨雾透明度上限 12%。

### 3.5 动效

| 场景 | 时长/曲线 | 说明 |
|---|---|---|
| 页面切换（一级 Tab） | 0 动画 | 保持 Tab 直觉，不做滑入 |
| 弹层升起 | 260ms `cubic-bezier(.22,.61,.36,1)` | 遮罩 180ms 渐显 |
| 日历选中 | 160ms 圆环扩散 | 只让填色从中心 0.9→1，不旋转 |
| 保存成功 | Toast 160ms 入 / 停留 1.6s / 160ms 出 | 不弹全屏成功页 |
| 分析中 | 骨架呼吸 1.4s `ease-in-out` 循环 | 配合阶段文案，不假装进度百分比 |
| 列表新增/删除 | 高度 200ms 折叠 | 让用户看到"变少了" |

禁止：区块逐个 fade-and-slide-up 入场、卡片 hover 抬升（移动端无 hover）、数字滚动计数动画。
`prefers-reduced-motion: reduce` 时全部降为 0ms。

## 4　布局骨架

画板 **390 × 844**（iPhone 14/15），同步检查 **360 × 780**。状态栏 44 + 安全区底部 20。

```
┌──────────────────────────────┐  390
│ 状态栏 44                     │
│ 页面头 48  ← 标题 22/600 / 右侧文字动作│
│                              │
│ 内容区  padding 0 22          │  单列，左对齐
│   …按 8/12/16/24 排           │  底部预留 88（给浮动底栏）
│                              │
│ 吸底元素（表单 CTA / 输入条）  │  内容下方 12 + 安全区
│ ┌ 浮动底栏 64，左右内缩 14 ┐   │  一级页固定，圆角 24
└──────────────────────────────┘
```

- **一级页**：有浮动底栏（`left/right:14`、`bottom:12`、高 64、圆角 24、模糊玻璃 + 柔影），无返回键，标题左对齐（首页不写「首页」，直接写日期 + 问候）。
- **二级页**（记录明细、皮肤历史/详情）：无底栏，顶栏 44：左返回箭头 + 居中标题（唯一允许居中的标题）+ 右侧次要动作。
- **底部弹层**：表单统一用 `HrSheet`，上沿 30 圆角、顶部 38×4 grabber，最大高度 88vh，头部左标题右「关闭」，底部 CTA 通栏 50 高、圆角 999，与安全区留 22。
- 键盘弹起：只滚表单区，CTA 与首页输入条始终贴键盘上沿。
- 内容滚动时底栏不下沉、不隐藏；页面内容允许被底栏盖住 12px 以内的装饰空白，但**不允许盖住文字**（故统一 88 底部内边距）。

- 退出登录：二次确认「退出后需要重新登录，记录不会删除」；确认后清空会话与页面缓存并回登录页。

## 7　状态与文案

| 场景 | 视觉 | 文案（可直接实现） |
|---|---|---|
| 列表为空（体重） | `HrEmpty` + 主按钮 | 还没有体重记录 / 记录第一次体重 |
| 列表为空（经期） | `HrEmpty` + 主按钮 | 还没有经期记录 / 记录第一次经期 |
| 列表为空（皮肤） | `HrEmpty` + 主按钮 | 还没有皮肤观察 / 拍照分析 |
| 加载中 | 骨架 2～3 行 | 不出现"加载中…"文字（分析页除外） |
| 请求失败（可重试） | `HrInlineAlert error` + 次按钮 | 数据没有加载成功 / 重试 |
| 保存中 | 按钮禁用 + 文案变化 | 保存体重 → 保存中 |
| 冲突 409（经期） | 表单内 error 条 | 11月3日已有一段经期（11月3日–11月7日），请检查日期 |
| 冲突 409（体重幂等） | 表单内 error 条 | 这笔记录已经保存过，刷新后可在明细里看到 |
| 过期 410（皮肤暂存） | 结果页顶部 error 条 + 主按钮 | 这张结果已过期，请重新拍一次 |
| 越权/不存在 404 | 二级页整页空态 | 这条记录不存在，或者不属于当前账号 |
| 模型不可用 | 结果页 error 条，表单仍可用 | 模型这次没有返回结果，手动记录不受影响 |
| 登录过期 401 | 直接回登录页 + Toast | 登录状态已过期，请重新登录 |
| 无记录问答 | 正文 + 主按钮 | 这个范围还没有体重记录，先记一笔就能看到变化 |

错误文案规则：说清**发生了什么**与**下一步**，不道歉、不写「系统繁忙」。

## 11　设计走查清单（演示前 15 分钟可过完）

1. 五个 Tab 的图标与中文标签齐全，选中态为 rose 胶囊 + rose 标签；点击后落在正确页面。
2. 首页日期、三个入口的状态行都取自当前账号真实数据；退出再登录后为空态而非上一次的残留。
3. 经期：日历四态同时可见；预计日期旁有依据说明；删除任一开始日后预测标记消失。
4. 体重：图注写明「每天取最后一次」；同日两笔只上图一个点，计数仍为两笔；无数据时按钮为「记录第一次体重」。
5. 皮肤：不保存直接返回，历史条数不变；保存后历史 +1；结果页无分数、百分比、病名。
6. 我的：生日不能选未来；身高非正数有 inline 提示；退出后业务页返回登录页。
7. 状态覆盖：至少走一遍「空 / 加载 / 失败 / 冲突 / 过期」五类界面，文案与第 7 节一致。
8. 360 与 390 两个宽度截图对照，无横向滚动、无文字截断。
9. 浮动底栏不遮挡任何文字：把每个一级页滚到底，最后一行与底栏之间仍有 ≥ 12px 空隙（对应内容区底部内边距 88）。
