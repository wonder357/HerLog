## 1　设计方向

**一句话**：这是给身体记账的一本纸页手册，不是一个糖果色的身体数据仪表盘。

`pic/` 里的四张参考图（美柚、好轻类产品）给了两条有效信息：目标用户是女性、产品语气要亲近；也给了三条要丢掉的东西：**高饱和粉紫渐变、玻璃球高光、促销条/对比排行**。前者与「记录」这件事无关，后者会把比赛演示的注意力从「我记了什么」拉走。

所以视觉取「纸 · 墨 · 胭脂」：

- **纸**：暖白纸底 `#FBF6F3`，块与块之间用**发丝线**和留白分隔，不靠阴影。
- **墨**：正文用带一点紫调的近黑 `#2B2229`，比纯黑柔，但对比度 14.5:1，长时间阅读不累。
- **胭脂**：主色取干玫瑰方向的胭脂红 `#B23A55`，一个颜色只做一件事——**用户的记录**与主操作。
- **梅紫**：`#5F4E6B` 只给「预测」和「AI 观察」。用户自己的数据用胭脂，系统算出来的用梅紫，两者在屏幕上永不混色。
- **衬线数字**：日期、kg、第 N 天、持续天数用衬线（Georgia / Songti SC），界面文字用黑体。数字一旦衬线化，页面立刻从「健康 App」变成「一本本子」。

### 与通用 AI 生成式 UI 的三处刻意偏离

| 默认做法 | 本方案 | 原因 |
|---|---|---|
| 每个信息块都是同半径白卡 + `rgba(0,0,0,.1)` 阴影 | 单页纸张流：发丝线分区，仅弹层/Toast/底栏有阴影 | 记录页信息密度高，卡片堆叠会把「今天记了什么」切碎 |
| 首屏 = 大数字 + 小标签 + 渐变色块 | 首屏 = 日期（衬线）+ 三个记录入口 + 对话 | 产品主行为是「记」，不是「看 KPI」 |
| 全大写小标签、`·` 连接元信息、按钮追加 `→` | 中文小标签用 13px 次级墨色；元信息用空格或换行；按钮只写动作 | 中文界面里这些西文排版手段会读成翻译腔 |

**唯一允许"抢眼"的地方**：经期日历。它是整个产品最有产品味道的元素，也是预测规则的可见证据（实色/虚线/点/深描边四态）。其余页面一律克制。

## 2　设计原则

1. **记录优先**：每屏首屏回答一个问题——「我要记什么」。状态、图表、建议都在其后。
2. **形状先于颜色**：日历四态、质量提示、AI 出处都用形状或位置区分，颜色只是加强。色弱用户与黑白截图都成立。
3. **纸与墨**：层级靠字重、字号、发丝线、留白。阴影只给真正浮起来的层（底部弹层、Toast、吸底输入条）。
4. **数字衬线、界面黑体**：数字有排版感，控件保持中性，两者不混用同一个字体族。
5. **AI 有边界**：AI 段落必带「AI 观察」标识与出处；只读问答的引用必定带日期范围与可跳转的记录入口。
6. **一个动作一个名字**：入口叫「记体重」，按钮就叫「保存体重」，成功提示就叫「体重已保存」。

## 3　设计令牌

### 3.1 色彩

| 令牌 | 值 | 用途 | 对比度（在纸底上） |
|---|---|---|---|
| `--hr-paper` | `#FBF6F3` | 页面底色 | — |
| `--hr-surface` | `#FFFFFF` | 底栏、弹层、输入框内壁 | — |
| `--hr-ink` | `#2B2229` | 标题、正文、数字 | 14.5 : 1 |
| `--hr-ink-2` | `#6B5F66` | 次级说明、时间、单位 | 5.7 : 1 |
| `--hr-ink-3` | `#9A8E93` | 占位符、禁用文字（不小于 14px） | 2.8 : 1（仅装饰/大字） |
| `--hr-line` | `#EBE0DC` | 发丝分割线 | — |
| `--hr-line-strong` | `#DCCCC7` | 输入框描边、选中描边 | — |
| `--hr-rouge` | `#B23A55` | 主操作、用户记录、强调 | 5.4 : 1（白字 5.8 : 1） |
| `--hr-rouge-soft` | `#F7E4E6` | 主操作浅底、用户气泡、实色日的浅底 | — |
| `--hr-rouge-mid` | `#D98396` | 图表线、非文字装饰 | — |
| `--hr-plum` | `#5F4E6B` | 预测、AI 观察、只读内容 | 7.0 : 1 |
| `--hr-plum-soft` | `#EFEAF3` | AI 段落底、引用 chip 底 | — |
| `--hr-sage` | `#55685C` | 已保存、图片质量正常、感受标记 | 5.6 : 1 |
| `--hr-sage-soft` | `#E7EDE8` | 感受标记浅底、成功条 | — |
| `--hr-warn` | `#9A5B27` | 提示条文字（非错误） | 5.9 : 1 |
| `--hr-warn-soft` | `#F6E8DC` | 质量偏暗、需重拍提示底 | — |

规则：`rouge` 与 `plum` **不得**同时出现在同一段落里；`sage` 只作状态，不作强调；正文字色永远是 `ink` 或 `ink-2`。

### 3.2 状态语义映射

| 状态 | 形状 | 色 | 文案示例 |
|---|---|---|---|
| 实际经期 | 实心圆填充 | rouge | 「经期第 3 天」 |
| 今日 | 数字下方 micro 标签 | ink-2 | 「今天」 |
| 有感受记录 | 数字下方 4px 圆点 | sage | 图例「有感受记录」 |
| 预计开始 | 1.5px 虚线圆环（不填充） | plum | 「预计开始」 |
| 选中日 | 外扩 2px 实线圆环 | ink | — |
| 已保存观察 | 左侧 3px 竖线 | sage | 「已保存」 |
| AI 内容 | 顶部「AI 观察」标识 + 左竖线 | plum | 「AI 观察 · 不用于诊断」 |
| 错误/冲突 | 左竖线 + 图标 | rouge | 「11 月 3 日已有一段经期」 |
| 需重拍/光线不足 | 左竖线 + 图标 | warn | 「这张照片偏暗，建议在自然光下重拍」 |

### 3.3 字体与字阶

字体族：

```
--hr-serif: Georgia, "Songti SC", "Source Han Serif SC", "Times New Roman", serif;
--hr-sans:  "PingFang SC", "HarmonyOS Sans SC", "Source Han Sans SC", "Microsoft YaHei", system-ui, sans-serif;
```

生产环境建议：数字衬线只打包 **Source Han Serif SC 数字子集**（约 8 KB woff2）；中文标题与正文仍走系统黑体，首屏不引入中文网络字体。

| 用途 | 字号 / 行高 | 字重 | 族 | 备注 |
|---|---|---|---|---|
| 登录产品名 | 34 / 44 | 400 | serif | 中文衬线在 iOS 与 Windows 差异大，Android 允许回退黑体 600 |
| 页面主数字（kg、第 N 天） | 44 / 48 | 300 | serif | 数字 + 单位分两级（单位 15px ink-2） |
| 页面标题 | 21 / 28 | 600 | sans | 左侧对齐，无居中标题 |
| 区块标题 | 16 / 24 | 600 | sans | 与上区块间距 24 |
| 正文 | 15 / 24 | 400 | sans | 行宽 ≤ 20 个汉字 |
| 说明/时间 | 13 / 20 | 400 | sans | ink-2 |
| 标签（chip） | 13 / 18 | 500 | sans | 内边距 8 × 12，圆角 999 |
| 数字表格（明细行） | 17 / 24 | 400 | serif | kg 数值 |
| 微文案（图例、出处） | 11 / 16 | 400 | sans | ink-2，不用大写 |

不使用：字间距 > 0.1em 的西文大写小标签、下标角标、`01/02/03` 编号（本研究内容不是序列）。

### 3.4 间距、圆角、描边、阴影

- 间距基数 4；常用节奏 **8 / 12 / 16 / 24 / 32**。页面左右内边距 **20**（360px 宽时 16）。
- 区块间距 24；同组元素 8～12；标题与内容 12。
- 圆角：输入框 12、面板/图片 16、底部弹层上沿 28、chip 999、日历日格 999（圆形）。**不统一圆角**，圆角大小即层级。
- 描边：统一 1px `--hr-line`；输入框与选中态 1.5px `--hr-line-strong`；不用 `box-shadow` 模拟边框。
- 阴影（仅三处）：
  - 底部弹层：`0 -12px 32px rgba(43,34,41,.10)`
  - Toast：`0 8px 24px rgba(43,34,41,.14)`
  - 吸底输入条：`0 -1px 0 var(--hr-line)`（其实还是线，不是影子）

### 3.5 动效

| 场景 | 时长/曲线 | 说明 |
|---|---|---|
| 页面切换（一级 Tab） | 0 动画 | 保持 Tab 直觉，不做滑入 |
| 弹层升起 | 260ms `cubic-bezier(.22,.61,.36,1)` | 遮罩 180ms 渐显 |
| 日历选中 | 160ms 圆环扩散 | 只让填色从中心 0.9→1，不旋转 |
| 保存成功 | Toast 160ms 入 / 停留 1.6s / 160ms 出 | 不弹全屏成功页 |
| 分析中 | 骨架呼吸 1.4s `ease-in-out` 循环 | 配合阶段文案，不假装进度百分比 |
| 列表新增/删除 | 高度 200ms 折叠 | 让用户看到"变少了" |

禁止：区块逐个 fade-and-slide-up 入场、卡片 hover 抬升（移动端无 hover）、数字滚动计数动画。
`prefers-reduced-motion: reduce` 时全部降为 0ms。

## 4　布局骨架

画板 **390 × 844**（iPhone 14/15），同步检查 **360 × 780**。状态栏 44 + 安全区底部 20。

```
┌──────────────────────────────┐  390
│ 状态栏 44                     │
│ 页面头 56  ← 标题 / 日期 / 操作│
│                              │
│ 内容区  padding 0 20         │  单列，左对齐
│   …按 8/12/16/24 排           │
│                              │
│ 吸底元素（表单 CTA / 输入条）  │  内容下方 16 + 安全区
│ 底栏 60 + 安全区 20           │  一级页固定
└──────────────────────────────┘
```

- **一级页**：有底栏，无返回键，标题左对齐（首页不写「首页」，直接写日期）。
- **二级页**（记录明细、皮肤历史/详情）：无底栏，顶栏 56：左返回箭头 + 居中标题（唯一允许居中的标题）+ 右侧次要动作。
- **底部弹层**：表单统一用 `HrSheet`，上沿 28 圆角，最大高度 88vh，内部可滚，头部左标题右「关闭」，底部 CTA 通栏 48 高，与安全区留 16。
- 键盘弹起：只滚表单区，CTA 与首页输入条始终贴键盘上沿。

## 6　逐页规格

### 6.1 登录 / 注册

```
┌ 390 ────────────────────┐
│                         │
│  她记                    │  serif 34，距顶 96
│  女性健康记录助手          │  13 ink-2，间距 8
│                         │
│  用户名                   │  HrField，距上 56
│  密码                     │  间距 20
│                         │
│  [        登录        ]   │  主按钮 48，距上 32
│                         │
│  还没有账号？注册          │  13，居中，rouge 部分可点
└─────────────────────────┘
```

- 不做插画、不做轮播、不做第三方登录。
- 注册态：主按钮「注册」，切换行「已有账号？登录」，标题下说明「用户名 2–32 个字符，区分大小写」。
- 反馈：重复用户名在用户名字段下 `rouge 13px`「这个用户名已被使用，换一个试试」；登录失败统一在密码字段下「用户名或密码不正确」（不区分哪个错）。
- 注册成功：回登录态，用户名已填入，密码清空，光标落密码框，Toast「注册成功，请登录」。
- 键盘弹起：主按钮跟随上移到键盘上方 16px，不被遮挡（H5 用 `position: sticky` + `env(safe-area-inset-bottom)`）。

### 6.2 首页

```
┌ 状态栏 ──────────────────┐
│ 11月18日 周三        小满 ○│  日期 serif 15/ink-2 + 用户名缩写头像
│ 今天记一笔，或者问我一句    │  15/ink，距上 8
├──────────────────────────┤
│ 记经期 │ 记体重 │ 拍照分析  │  HrIndexTabs 高 96
│ 第3天  │ 56.8kg│ 11月12日  │  状态行 12
├──────────────────────────┤
│ 试试这样问                │  13 ink-2
│ [这周体重有变化吗][上次…]  │  建议问题 chips
│                          │
│        这周体重有变化吗？  │  用户气泡 rouge-soft 右对齐，最大宽 78%
│                          │
│ │ 11月12日–11月18日       │  plum 竖线 + 范围
│ │ 这七天记录了 5 次体重，   │  正文 15/24
│ │ 11月12日 57.2 kg…       │
│ │ [体重明细 5 次记录]      │  引用 chip，可跳转
│                          │
│  [问我一个关于记录的问题][↑]│  吸底输入条 52 + 安全区
└──────────────────────────┘
```

- 首屏不出现图表、不做问候语堆砌；日期是唯一"大"的视觉元素，用衬线。
- 用户气泡靠右 78% 宽、`rouge-soft` 底、圆角 16（右下 4）；AI 回答不套气泡，走纸面正文 + 左侧 2px plum 竖线，避免"聊天 App"观感压过"记录"观感。
- 无记录时回答：「这个范围还没有体重记录，先记一笔就能看到变化」+ 主操作「记体重」。

```
┌ ‹ 观察结果 ────────────┐
│ ┌ 图片 4:3 ┐            │  原图（真机）/ 纸底示意位
│ 下巴  11月18日 21:04     │
│ ⚠ 光线偏暗，部分细节看不清，建议在自然光下重拍 │  warn 条

│ │ 可见外观                │  三段：标题 15/600 + 正文 15/24

│ │ 看不清之处               │
│ │ 光线偏暗，右侧边缘…      │
│ │ 值得留意                │  这一段标题带 plum 5px 点，正文仍 ink
│ │ 同一部位短期内反复出现…   │
│ [不保存] [重拍] [  保存  ] │  文字 / 次 / 主
└────────────────────────┘
```

- 三段顺序固定：`visible` → `unclear` → `attention`，中文标题「可见外观 / 看不清之处 / 值得留意」，不出现分数、百分比、病名、"改善"字样。三段共用一个 2px `plum` 左竖线，表示整块都是模型输出。
- 结果底部一行 11px 写模型 ID、推理用时与保存后果（示例「模型 herlog-vision v1　推理 2.4 s　保存后进入历史」），三项都取接口返回值，不写死。
- `quality.level = limited` 时，警示条在三段之上；`good` 时不出条。
- `demo_sample = true` 时，出处行改为「演示样例 · 未调用模型推理」，并保留模型 ID 展示位置为空。
- 流程步骤（选部位 → 说明 → 拍照/选图 → 分析中 → 结果）用**单页内分步**，不做 5 个独立路由；步骤指示只用顶部一行文字「第 2 步，共 3 步」，不做圆点进度条。
- 发送前说明必须出现一次：「照片会发给模型服务，只用于本次分析」。
- 分析中：`HrSkeleton` 三段 + 阶段文案轮换「正在读取可见外观」「正在整理看不清之处」，不显示假百分比。
- 失败：保留已选图片与部位，`HrInlineAlert error`「这次分析没有完成，可以重试」+ 主操作「重试」、次操作「换一张」。
- 保存冲突（并发同 `analysis_id`）：按后端返回同一条处理，直接进历史详情，不报错。
- 过期（410）：「这张结果已过期（10 分钟内需保存），请重新拍一次」。
- 历史：

```
┌ ‹ 皮肤历史 ──── 筛选：全部 ▾┐
│ ┌──┐ 下巴  11月12日        │  缩略图 64 + 部位 + 日期 + visible 一行省略
│ ┌──┐ 额头  11月05日        │
│ ┌──┐ 下巴  10月28日        │
└────────────────────────────┘
```
- 详情页显示原图（H5 先取 token 再取 Blob，卸载时 `URL.revokeObjectURL`），图片失败时显示 16 圆角占位 + 「图片没有加载成功」。

## 11　设计走查清单（演示前 15 分钟可过完）

1. 五个 Tab 的图标与中文标签齐全，选中态为 rouge 胶囊 + rouge 标签；点击后落在正确页面。
2. 首页日期、三个入口的状态行都取自当前账号真实数据；退出再登录后为空态而非上一次的残留。
3. 经期：日历四态同时可见；预计日期旁有依据说明；删除任一开始日后预测标记消失。
4. 体重：图注写明「每天取最后一次」；同日两笔只上图一个点，计数仍为两笔；无数据时按钮为「记录第一次体重」。
5. 皮肤：不保存直接返回，历史条数不变；保存后历史 +1；结果页无分数、百分比、病名。
6. 我的：生日不能选未来；身高非正数有 inline 提示；退出后业务页返回登录页。
7. 状态覆盖：至少走一遍「空 / 加载 / 失败 / 冲突 / 过期」五类界面，文案与第 7 节一致。
8. 360 与 390 两个宽度截图对照，无横向滚动、无文字截断。
