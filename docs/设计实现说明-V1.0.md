## 0　起点与假设

需求文档把开发起点放在两个岐问仓库（`qiwen-health-app-v2@dw` / `qiwen-health-api@test-cht-feat`）。
当前工作目录里只有文档、随包 Alembic 迁移、compose 配置和演示图片，没有这两个仓库的检出，也没有 Node / Python / Docker。

因此这版按文档约定的技术栈与接口契约**从零实现**一份可运行的比赛分支：

- 语言与框架：FastAPI + SQLAlchemy 2 + Alembic + MySQL 8（后端），uni-app / Vue 3 / Pinia（H5 前端）。
- 表名、接口路径、字段名、响应信封、计算口径与文档逐项对齐，便于后续把代码搬回岐问仓库。
- 迁移链按文档重建了父提交 `h9b0c1d2e3f4`（会员表基线），随包迁移 `20261118_herlog.py` 原样放在其后，保证 `alembic heads` 只有一个 head。
- 本机工具链装在项目内 `.tools/`（Python 3.12.9 便携版 + Node 22.16.0），不进 Git。

**未做**：没有实现文档里的旧业务（餐食、旧 Tab、旧方案日历、XYZ 客户主档、机构目录）。比赛五页不需要它们。

## 2　数据模型

沿用文档 4.2 的五张表与会员表，统一前缀 `qwhealth_herlog_`：

| 表 | 关键约束 |
|---|---|
| profile | `customer_id` 主键、`username` 唯一（MySQL `utf8mb4_bin`，区分大小写）、身高 `CHECK > 0` |
| period | 同账号 `start_day` 唯一，`end_day >= start_day`；写入前锁会员行再查区间 |
| feeling | `(customer_id, day)` 复合主键，按日覆盖，`symptoms` JSON |
| weight | `grams` 正整数，`(customer_id, client_key)` 唯一，`(customer_id, measured_at, id)` 索引 |
| skin | `(customer_id, analysis_id)` 唯一，图片 `MEDIUMBLOB`，记录 `model_id` 与 `prompt_version` |

实现上的两点：

1. **会员表可空手机号**。会员仍复用 `qwhealth_member_auth`，用户名会员的 `phone` 写 `NULL`，联系号码只放 `profile.contact_phone`；`org_id` 由本迁移补列。会话复用 `qwhealth_member_auth_session`，库里只存 token 的 `sha256`，退出即写 `revoked_at`。
2. **ORM 与迁移同源不同方言**。ORM 用 `with_variant` 描述 MySQL 特有的 `DATETIME(3)`、`MEDIUMBLOB`、二进制排序规则，因此同一份模型能在 SQLite 上跑测试、在 MySQL 上跑迁移。

## 3　接口

全部挂在 `/api/v1/c`，成功固定 `{"code":200,"message":"success","data":...}`，失败用对应 HTTP 状态码 + 可展示 `message`。请求头 `token`（同时接受 `Authorization: Bearer`）。

| 方法与路径 | 说明 |
|---|---|
| POST `/auth/username-register`、`/auth/username-login` | 唯一两个匿名入口；重名 409、错密码 401（与未知用户同一句文案） |
| GET `/auth/me`、POST `/auth/logout` | 刷新恢复会话、撤销会话 |
| GET / PUT `/herlog/profile` | 生日不得晚于今天、身高为正数、电话可空可清 |
| GET / POST `/herlog/periods`、PUT / DELETE `/herlog/periods/{id}` | 返回 `items`（含持续天数与间隔）、`prediction`、`status`；日期冲突 409 并指出冲突日期 |
| GET `/herlog/feelings?from&to`、PUT / DELETE `/herlog/feelings/{day}` | 按日覆盖；全字段清空等同删除 |
| GET / POST `/herlog/weights`、PUT / DELETE `/herlog/weights/{id}` | `client_key` 幂等：内容一致返回原记录，内容不同 409 |
| GET `/herlog/weights/summary?days=7\|30` | `latest / count / points / delta_kg / suggestion` |
| POST `/herlog/skin/analyze`、DELETE `/herlog/skin/pending/{analysis_id}` | 分析结果先进暂存，不进历史 |
| POST / GET `/herlog/skin/observations`、GET `/herlog/skin/observations/{id}`、GET `.../image` | 保存幂等；过期 410；图片需 token 且 `Cache-Control: private, no-store` |
| POST `/herlog/assistant/query` | 只读问答，返回 `answer / domain / range / record_refs` |

## 4　计算口径

### 4.1 经期预测（`app/logic/period.py` ↔ `client/src/shared/period.ts`）

- 去重后按开始日倒序取最近 4 次；不足 3 次不预测。
- 相邻开始日求自然日间隔；间隔极差 > 7 天隐藏预测，等于 7 天仍估算。
- 2 个间隔取均值四舍五入，3 个间隔取中位数；预计开始日 = 最近开始日 + 估算天数。
- 预计日期早于今天时状态为 `overdue`，只提示补记，不自动顺延、不写成实际记录。
- 只有新增 / 修改 / 删除开始日才重算预测；改结束日或感受只刷新实际记录。

### 4.2 体重统计（`app/logic/weight.py` ↔ `client/src/shared/weight.ts`）

- 输入 kg 最多三位小数 → 正整数克；同一自然日只取最后一次进图。
- `count` 统计范围内全部测量；`delta` 取图上首尾两个不同记录日；不足两点为 `null`。
- 范围按 Asia/Shanghai 自然日左闭右开（`local_day_start_utc` / `local_day_end_utc`）；库里存 UTC。
- 建议文案由规则匹配（同日多笔、只有一天、变化很小等），不含因果推断。

两侧用同一组输入与期望值验收：同日 56.8 / 57.0 kg，第三天 56.6 kg → 三笔、两个点、−0.4 kg。

## 5　AI 接入与边界

`app/services/vision.py` 只有两个明确调用：

- `observe_skin(image, site)`：`live` 模式调 OpenAI 兼容 `chat/completions`，输出必须是 `{visible, unclear, attention, quality}` 的 JSON，字段缺失或超时抛 503 并提示可重试；`fixture` 模式返回带「演示样例」标记的固定文案，用于现场断网。
- `answer_question(facts, question)`：`live` 模式只让模型解释服务端算好的数字；`fixture` 模式返回 `None`，由服务端用固定文案回答。

问答先定模块与日期范围再取数：识别体重 / 经期 / 皮肤关键词，跨模块归因（如「是不是来月经才长痘」）直接拒绝并让用户选择查看哪类记录；「帮我记 56.8 kg」返回「记体重」入口，不写库。客户端只提交 `question`。

图片链路：前端缩到 1024 长边重编码 JPEG → 服务端校验 base64、≤3 MiB、JPEG/PNG、可解码、像素上限 → 暂存（Redis `setex` + 每账号上限 3 条，无 Redis 时退化为进程内实现）→ 用户确认保存时再落库，事务提交后删暂存。

## 6　前端结构

- **导航**：`pages.json` 注册 5 个一级页（home / period / weight / skin / me）与 3 个二级页（登录、体重明细、皮肤历史）；`tabBar.list` 同名同序；一级页统一 `uni.switchTab`，二级页 `uni.navigateTo`。底栏由 `components/TabBar.vue` 绘制（`App.vue` 里 `uni.hideTabBar` 隐藏原生栏），路径只维护这一份。
- **会话**：`services/httpClient.ts` 统一带 `token`、拆信封、401 清缓存回登录页；`stores/auth.ts` 负责登录 / 注册 / `restore` / `refresh`（`/auth/me`）/ 退出。`httpClient` 用会话 epoch 丢弃切换账号后的迟到响应。
- **共享表单**：`WeightForm` / `PeriodForm` / `FeelingForm` 同时被首页快捷入口和业务页使用，提交同一 API；保存中禁用重复点击，保存成功后由发起页通知并触发 `onShow` 重取。
- **刷新**：各业务页 `onShow` 按当前账号重取；删除对话框写明日期、类型与后果。
- **皮肤**：选部位 → 说明照片会发给模型 → 拍照 / 选图 → 分析中 → 结果页（可见外观 / 看不清 / 值得留意 + 质量提示）；保存、不保存、重拍分别对应 `observations` 与 `pending` 接口；历史按部位筛选，详情图片走鉴权请求取 Blob 并在卸载时 `revokeObjectURL`；同部位两条可选文字对比。

## 8　已知限制与下一步

1. **H5 产物**：本机用 uni-app 3.0.0 alpha 依赖（Compiler 5.37）构建通过，产物在 `client/dist/build/h5`；`dist/` 与 `node_modules/` 不入 Git。正式验收仍以目标机的 `npm ci && npm run build:h5` → `dist/build/h5` 为准。
2. **MySQL 在线升级**：本机没有 Docker，`alembic upgrade head` 只做了离线 DDL 校验，没在真实 MySQL 8 上跑过。目标机先用 `docker compose up -d --wait` + `/health` 确认 `mysql: ok` 再执行升级。
3. **真实推理**：首页「DeepSeek 对话」默认调用 DeepSeek 流式接口。启动后端时加载包含 `HERLOG_MODEL_API_KEY` 的服务端环境文件，例如使用 Uvicorn 的 `--env-file` 参数。模型默认 `deepseek-flash`，可通过 `HERLOG_MODEL_ID` 配置。`/health` 的 `assistant_model_mode` 和 `assistant_key_configured` 可核对后端配置。首页演示回复需显式设置 `HERLOG_ASSISTANT_MODEL_MODE=fixture`。皮肤观察使用独立的 `skin_model_mode` 状态验收。
4. **前端样式稿**：`docs/design/` 下的视觉稿与 `docs/前端样式设计规范-V1.1.md` 由同目录的其它工作产出，当前页面只实现了基础视觉（颜色、间距、底栏），未逐屏对齐视觉稿。
5. **未实现的可选项**：皮肤两次对比的 AI 总结（当前只并排展示已保存文字）、健康设备接入、手机号登录、账号注销。

## 9　本地运行

后端（容器提供 MySQL 8 与 Redis 7，见 `docs/compose.yaml`）：

```powershell
# 1. 基础服务
$kit = 'C:\path\to\docs'   # compose.yaml 所在目录
$dbPass = [guid]::NewGuid().ToString('N'); $rootPass = [guid]::NewGuid().ToString('N')
@("HERLOG_DB_PASSWORD=$dbPass","HERLOG_DB_ROOT_PASSWORD=$rootPass") | Set-Content -Encoding ascii .\infra.env
docker compose --env-file .\infra.env -f "$kit\compose.yaml" up -d --wait

# 2. 后端
cd backend
@("ENV=contest","MYSQL_HOST=127.0.0.1","MYSQL_PORT=13306","MYSQL_DATABASE=herlog_contest",
  "MYSQL_USER=herlog","MYSQL_PASSWORD=$dbPass","REDIS_HOST=127.0.0.1","REDIS_PORT=16379",
  "REDIS_DB=0","REDIS_ENABLED=true") | Set-Content -Encoding ascii .env.contest
python -m alembic upgrade head
python -m uvicorn app.main:app --host 127.0.0.1 --port 8000 --reload
```

`ENV=contest` 时不启动后台调度器（`app/main.py` 里的 `_scheduler_enabled()`），Redis 与数据库生命周期不受影响。

前端：

```powershell
cd client
'VITE_API_BASE_URL=http://127.0.0.1:8000' | Set-Content -Encoding ascii .env.development.local
npm install
npm run dev:h5          # http://127.0.0.1:5173
npm run build:h5        # 产物 dist/build/h5
npm run test:logic      # 纯计算规则
```

后端 CORS 已允许 `http://localhost:5173`、`http://127.0.0.1:5173`、`http://localhost:8080` 与 `token` 请求头。
