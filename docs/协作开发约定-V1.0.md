## 1　角色、分支与 Tag 分工

本项目的“tag”指**按交付范围打的开发标记**：一个人一个范围，范围完成并验收后再打 Git tag 归档。四个范围如下：

| 范围 | 开发 tag | 建议分支 | 负责人 | 主要文件 |
|---|---|---|---|---|
| 主体样式 | `style-main` | `main-chy`（当前本人分支） | 本人 | `client/src/styles/*`、`client/src/components/hr/*`、`client/src/App.vue`、`client/src/pages.json`、全局字体/色彩令牌 |
| 首页 | `home` | `tag/home` | 队友 | `client/src/pages/home/index.vue`、`client/src/services/assistantService.ts` |
| 经期 | `period` | `tag/period` | 队友 | `client/src/pages/period/index.vue`、`client/src/components/PeriodForm.vue`、`FeelingForm.vue`、`client/src/shared/period.ts` |
| 皮肤 | `skin` | `tag/skin` | 队友 | `client/src/pages/skin/*.vue`、`client/src/services/skinService.ts`、`client/src/utils/image.ts`、`skinDraft.ts` |

**当前仓库状态**：只有 `main`（集成分支）与 `main-chy`（本人分支），上述 `tag/*` 分支和 Git tag 尚未创建。本次先把约定与现有代码合入 `main`；后续每人按下面流程开分支、打 tag。

### 1.1 分支与 tag 命名

- 集成分支：`main`，**不允许直接提交**。
- 本人长期分支：`main-chy`；队友分支按范围命名：`tag/home`、`tag/period`、`tag/skin`。
- 一个 tag 分支只做一个范围，不跨范围改文件。确有交叉改动时，先在群里说明，再由该范围负责人改。
- 验收通过后打 **annotated tag**，命名 `v1.0-<tag>`，例如 `v1.0-home`；tag 一旦推送不得移动或删除：

```powershell
git tag -a v1.0-home -m "首页 tag 验收通过"
git push origin v1.0-home
```

- 合并顺序：`main` → 拉出自己的 tag 分支 → 开发 → 本地自测（第 5 节）→ 推送分支 → 合并回 `main` → 打 tag → 删除已合并的临时分支。
- 合并前先 `git fetch origin && git rebase origin/main`，避免把过期代码合回去。

### 1.2 文件所有权与冲突处理

- `client/src/styles/tokens.scss` 等样式令牌由**本人维护**；队友需要新令牌时提需求，不直接改令牌文件。
- `pages.json`、`TabBar.vue` 的路由/底栏配置由本人统一维护；队友新增页面时只改自己页面文件，并通知本人补登记。
- 公共组件（`HrSheet`、`HrButton` 等）由本人维护接口契约；队友只按 props 使用，不修改组件内部。
- 后端 `backend/` 与数据库结构由本人维护；队友需要接口或字段变更时先沟通，不自行改表或生成迁移。

两人处于**同一局域网**，共用本人机器上的 MySQL / Redis / 后端服务。当前本机局域网 IP 为 `10.20.30.108`（如变更，须同步给队友并更新下文配置）。

### 2.1 本人（服务提供方）启动

```powershell

#    infra.env 存放密码，不进 Git

# 2) 数据库迁移（只由本人执行一次，见 3.2）

python -m alembic upgrade head

# 3) 后端监听所有网卡，队友才能访问
python -m uvicorn app.main:app --host 0.0.0.0 --port 8000

# 4) 健康检查
Invoke-RestMethod http://127.0.0.1:8000/health
```

`/health` 返回中 `mysql` 与 `redis` 均为 `ok` 才算环境就绪。
> 注意：把数据库端口暴露到局域网仅限可信网络；请在 Windows 防火墙中只放行队友机器 IP，且不要使用弱密码。演示结束后可把 `docs/compose.yaml` 的端口改回 `127.0.0.1`。

### 2.2 队友（前端开发方）配置

队友只跑前端，API 指向本人机器。在 `client/` 下新建 `.env.development.local`（该文件已被 `.gitignore` 忽略，不要提交）：

```dotenv

```

```powershell

```

后端 CORS 已允许 `http://localhost:5173` 与 `http://127.0.0.1:5173`，队友在本机用这两个地址访问不会跨域。若改成用局域网 IP 打开前端页面（如 `http://10.20.30.108:5173`）被 CORS 拦截，需由本人在 `backend/app/main.py` 的 `allow_origins` 中追加该来源。

若队友也需要跑一份后端（例如调试接口），除上述 API 地址外，还需在 `backend/.env.contest` 中配置：

## 3　数据库约定

### 3.1 连接与库表

| 项 | 值 |
|---|---|
| 引擎 | MySQL 8.0，`mysql+pymysql`，`charset=utf8mb4` |
| 连接串 | `mysql+pymysql://herlog:<密码>@10.20.30.108:13306/herlog_contest?charset=utf8mb4` |
| 库名 | `herlog_contest` |
| 排序规则 | `utf8mb4_0900_ai_ci`；用户名字段用 `utf8mb4_bin`（区分大小写） |
| 表前缀 | `qwhealth_herlog_*`（profile / period / feeling / weight / skin），会员表 `qwhealth_member_auth*` |
| 当前迁移版本 | `herlog_20261118`（head，单 head） |

### 3.2 迁移与 DDL 纪律

- **只有本人执行** `alembic upgrade head` 及任何 DDL 变更。队友不要运行 `alembic upgrade` / `downgrade` / `revision --autogenerate`。
- 需要改表时，队友在分支上写清需求，由本人统一出迁移脚本、在本地验证后升级共享库，并通知大家刷新。
- 新增 ORM 模型时先登记已有 revision，不要让 autogenerate 为同一张表重复生成 DDL。
- 共享库升级前先备份：`mysqldump -h 10.20.30.108 -P 13306 -u herlog -p herlog_contest > backup-YYYYMMDD.sql`（备份文件放本地，不进 Git）。

### 3.3 数据与事务口径

- 所有业务数据按 `customer_id` 隔离；**每人用自己的测试账号**（如 `dev_chy` / `dev_teammate`），不读写对方账号的数据。
- 时间统一以 UTC 入库，按 `Asia/Shanghai` 自然日统计与展示；不要在前台自行换算后写库。
- 体重用整数克存储，同一自然日可多笔，趋势图每天只取最后一次；`client_key` 用于幂等，重试沿用同一个键。
- 经期同一账号 `start_day` 唯一，重叠返回 409；感受按 `(customer_id, day)` 覆盖，全字段清空等同删除。
- 皮肤图片不落地成文件：前端缩放编码后以 base64 上传，暂存于 Redis（无 Redis 时退化为进程内），用户确认保存时才与文本同一事务写入 `skin.image_bytes`（`MEDIUMBLOB`）。
- **禁止**对共享库执行 `DROP TABLE`、`TRUNCATE`、无 `WHERE` 的 `UPDATE/DELETE`。需要清理测试数据时按 `customer_id` 精确删除，并先告知对方。

### 3.4 环境文件

以下文件含密码或私有配置，**一律不提交**：`infra.env`、`.env`、`.env.contest`、`.env.*.local`、`*.bundle`。`.gitignore` 已覆盖，新增类似文件时要先确认忽略规则生效（`git check-ignore -v <文件>`）。

## 4　前端图片位置

| 位置 | 用途 | 是否进 Git | 引用方式 |
|---|---|---|---|
| `pic/`（仓库根） | 竞品与设计参考图（现有 4 张 jpg） | 是，但只读 | 不参与构建，仅文档参考 |
| `docs/design/` | 视觉稿 HTML / PNG | 是，只读 | 浏览器打开，不作为运行时资源 |
| `client/src/static/` | **运行时静态资源**：TabBar 图标、占位图、演示图 | 是 | `/static/xxx.png`（uni-app 约定） |
| `client/src/static/demo/` | 皮肤「演示样例」图片 | 是 | `/static/demo/xxx.jpg` |
| 数据库 `skin.image_bytes` | 用户上传的皮肤原图 | 否（存库） | 经鉴权接口 `GET .../image` 取 Blob |

规则：

1. **页面里用到的图片一律放 `client/src/static/`**，不要放仓库根 `pic/`，也不要用绝对路径指向本机磁盘。
2. 命名用小写 kebab-case + 语义前缀：`hr-tabbar-home.png`、`hr-tabbar-home-active.png`、`demo-skin-chin.jpg`；不用中文、空格、大写。
3. 底栏图标按设计规范每个 Tab 出两色（未选中 `--hr-ink-3` / 选中 `--hr-rouge`），命名保持 `hr-tabbar-<页>-active` 成对出现，由本人统一登记到 `pages.json` 与 `TabBar.vue`。
4. 皮肤用户照片**不是静态资源**：前端 `client/src/utils/image.ts` 把选图缩到长边 1024、按 JPEG quality 0.85 重编码后 base64 上传；服务端限制 ≤3 MiB、像素 ≤40,000,000、JPEG/PNG、可解码。结果页用 `URL.createObjectURL` 预览，卸载时 `URL.revokeObjectURL`。
5. 新增演示图前先确认体积与授权；非必要大图不要进 Git。图片加载失败要有 16 圆角占位与「图片没有加载成功」文案。

## 5　测试运行配置

### 5.1 后端（在 `backend/` 目录）

环境：Python ≥ 3.12，依赖见 `backend/pyproject.toml`。单测用内存 SQLite，**不依赖共享 MySQL**，可随时跑。

```powershell
cd backend
python -m pytest -q                       # 43 项，应全部通过
python -m alembic heads                   # 应只有 herlog_20261118 (head)
python -m alembic upgrade head --sql      # 离线 DDL 校验，不连库
```

### 5.2 前端（在 `client/` 目录）

环境：Node 22（项目内 `.tools/node` 可用）。`node --experimental-strip-types` 需要 Node ≥ 22。

```powershell
cd client
npm ci
npm run test:logic          # node:test，13 项纯计算规则
npm run typecheck:shared    # tsc strict，应无错误
npm run build:h5            # 产物 dist/build/h5/index.html
```

### 5.3 夜间测试运行器

```powershell
powershell -NoProfile -ExecutionPolicy Bypass -File .\scripts\nightly-test.ps1
```

- 依次执行：文档/资产完整性 → 后端编译 + pytest + 可选 ruff + alembic heads → 前端依赖/检查/构建 → compose 配置校验。
- 报告写入 `artifacts/nightly/<时间戳>/`，含 `report.md`、`summary.json`、各步骤日志；`artifacts/` 已被 `.gitignore` 忽略。
- 失败时生成 `artifacts/nightly/ALERT.txt`，成功自动清除。
- 可加 `-SkipStatic` / `-SkipBackend` / `-SkipFrontend` / `-SkipInfra` 跳过某步；`-ApiPath`、`-ClientPath` 可指定仓库路径。

### 5.4 合并前检查清单

- [ ] 后端 `python -m pytest -q` 全绿，`alembic heads` 单 head。
- [ ] 前端 `npm run test:logic`、`npm run typecheck:shared`、`npm run build:h5` 全通过。
- [ ] 本人机器 `/health` 显示 `mysql: ok`、`redis: ok`（或用内存暂存时 `redis: disabled`）。
- [ ] 夜间运行器无 FAIL；若有 WARN 已确认原因。
- [ ] 本次改动未包含 `.env*`、`infra.env`、`*.bundle`、个人照片或大体积无关文件。
- [ ] 交叉文件（令牌、`pages.json`、公共组件、数据库结构）已与对方确认。
- [ ] `git status` 干净后推送，合并到 `main` 再打 `v1.0-*` tag。
